# Парсер отзывов Wildberries

Собирает отзывы покупателей с оценкой 1–5 и метаданные товаров (название, категория, бренд, описание, средний рейтинг) с Wildberries. Аккаунт и API-ключи не нужны.

## Почему Wildberries

| Площадка | Что проверили | Итог |
|---|---|---|
| **Wildberries** | Отзывы отдаются публичным JSON (`feedbacks{1,2}.wb.ru/feedbacks/v1/{imt_id}`): до ~500 отзывов на товар за один запрос, с оценкой, плюсами и минусами. Карточки товаров лежат на статическом CDN (`basket-XX.wbbasket.ru/.../card.json`) | ✅ самый простой вариант |
| Ozon | Главная и `composer-api` редиректят (307) на антибот-челлендж | ❌ нужен headless-браузер и обход антибота |
| Яндекс Маркет | Отзывы рендерятся JS, есть капча | ❌ |
| Avito | Отзывы привязаны к продавцам, а не к товарам; рендер через JS | ❌ |

Нюанс: поиск и каталог WB (`search.wb.ru`, `catalog.wb.ru`) из-за антибота отдают 403 для нероссийских IP. Поэтому товары берутся **случайной выборкой `nm_id`** через CDN. Плюс такого подхода: выборка не смещена в сторону популярных товаров из поисковой выдачи и покрывает все категории.

## Как работает

1. Берётся случайный `nm_id` из диапазона (по умолчанию 10M–900M).
2. Определяется хост CDN `basket-XX` для `vol = nm_id // 100000`. Хосты закреплены за возрастающими диапазонами vol; найденный хост кэшируется.
3. Из `card.json` берутся `imt_id` (группа товара, общая для всех цветов и размеров), название, категория, бренд и описание.
4. По `imt_id` загружаются отзывы. Остаются отзывы с оценкой и непустым текстом (≥10 символов в text+pros+cons). Товары, у которых таких отзывов меньше 3, пропускаются. С одного товара берётся не больше 100 случайных отзывов, чтобы несколько популярных товаров не забили датасет.
5. Результат дописывается в JSONL. Парсер можно прервать и перезапустить: уже обработанные товары пропускаются.

## Запуск

```bash
pip install -r parser/requirements.txt
python parser/wb_parser.py --target 30000 --out data/raw --seed 42   # сбор
python parser/export.py --raw data/raw --out data                     # сборка датасета и статистика
```

Полезные флаги: `--max-per-product`, `--min-reviews`, `--min-len`, `--concurrency`, `--nm-min/--nm-max`.

## Выходные файлы (`data/`)

- `wb_reviews.csv`: все отзывы (170 МБ, в git не лежит, т.к. больше лимита GitHub). В репозитории лежит сжатая копия `wb_reviews.csv.gz`, pandas читает её напрямую. Ключевые поля: `rating` (метка 1–5), `full_text` (text + «Достоинства» + «Недостатки»), `text`, `pros`, `cons`, `created_date`, `imt_id`, `product_name`, `brand`, `subject`, `subject_root`, `votes_plus/minus`.
- `wb_reviews_balanced.csv`: сбалансированная версия. Из больших бинов удалены случайные отзывы, на каждую оценку столько же, сколько в самой редкой (2★).
- `wb_products.csv`: товары: `name`, `description`, `options`, `subject`, `brand`, `avg_rating`, `feedback_count`. Пригодится для постановки «рейтинг товара по описанию».
- `wb_reviews_sample.csv`: по 10 случайных отзывов на каждую оценку, чтобы глазами проверить, что данные адекватные.

Разведочный анализ: `EDA.ipynb` в корне репозитория.

## Что собрано (07.10.2026, два прогона: `--target 30000 --seed 42` и дозапуск `--target 300000 --seed 43 --concurrency 32`, ~50 минут суммарно)

- **300 118 отзывов** с оценкой, **9 172 товара**, 93 корневые и 1 930 конечных категорий. Просмотрено ~126k карточек: у большинства случайных товаров нет хотя бы 3 текстовых отзывов.
- Распределение оценок: `1★ 7.3% · 2★ 2.8% · 3★ 5.9% · 4★ 8.2% · 5★ 75.8%`. Классы **сильно несбалансированы**.
- Balanced-версия: **42 455 отзывов**, по 8 491 на оценку.
- Длина `full_text`: медиана 60 символов (8 слов), p95 ≈ 240 символов.
- На товар: медиана 14 отзывов, максимум 100 (ограничение парсера). При разбиении на train/test стоит делать **group split по `imt_id`**.
- Иногда пользователи пишут жалобы в поле «Достоинства», поэтому лучше использовать склеенный `full_text`.
